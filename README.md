## 本地运行

环境要求：Node.js `^20.19.0` 或 `>=22.12.0`，以及 npm。

```bash
npm install
npm run dev
```

前端默认地址为 `http://localhost:5173`，后端为 `http://127.0.0.1:3000`，健康检查为 `GET /health`。

如需让同一 Wi-Fi 下的手机访问电脑上的开发版：

```bash
npm run dev:network
```

然后在手机浏览器打开终端显示的局域网地址。正式部署后，电脑和手机直接访问同一个 HTTPS 网页即可。

## 生产部署

先运行 `npm run build`。将 `frontend/dist` 作为静态网站部署，并运行 `npm start --workspace @sztu-gpa/backend` 启动 API；网关需把网页的 `/api/*` 和 `/health` 转发至后端。若前后端使用不同域名，请在构建前设置 `VITE_API_BASE_URL` 为 API 的 HTTPS 地址，并按部署域名收紧后端 CORS。

## 浏览器与设备

- 支持现代 Chrome、Edge、Firefox、Safari 及相应的手机浏览器。
- 不需要安装插件、浏览器扩展或桌面软件。
- 电脑端可拖入一张或多张截图，也可点击选择文件。
- 手机端点击上传区后可从相册或“文件”中选择截图。
- 最推荐直接从教务系统复制包含表头的成绩表并粘贴；系统会按制表符读取真实单元格，不经过 OCR。
- 支持拖入或选择 XLS、XLSX、CSV、TSV 成绩单，电脑和手机均无需安装插件。
- 支持 PNG、JPG/JPEG、WEBP、BMP 和静态 GIF；暂不直接支持 HEIC。
- 每批最多 8 张，单张不超过 12 MB，总计不超过 60 MB，避免手机浏览器内存不足。
- 成绩数据保存在当前浏览器中，同一账号在不同电脑或手机之间暂不会自动同步，可通过 JSON 备份迁移。

## 截图 OCR 说明

截图 OCR 已调整为兼容入口。导入方式按准确性排序为：复制粘贴成绩表、Excel/CSV、截图 OCR。

- 截图内容由浏览器中的 WebAssembly OCR 引擎处理，应用不会向用户索取教务系统帐号或密码。
- 首次使用会从 Tesseract 公开模型源下载中英文识别模型；之后将由浏览器缓存。成绩图片本身不经过本应用的后端。
- 系统会在识别前按文件内容删除相同截图，并在识别后清理重叠截图产生的相同课程行；删除时会向用户显示数量。
- OCR 从不自动写入成绩档案：用户可逐条确认，也可点击“一键全部通过审核”。缺失或冲突记录不会被批量通过。

## 结构化导入说明

- 复制粘贴和 CSV/TSV 使用 Papa Parse 5.7；Excel 使用固定版本的 SheetJS CE 0.20.3。
- 系统会扫描表头并匹配常见别名，例如“课程编号/课程代码”“成绩/总评成绩”“等级/成绩等级”。
- 数字成绩、等级和绩点会按 SZTU 规则交叉校验；冲突行不会被一键通过。
- F、补考和 P/NP 保持为独立课程尝试，不会用补考覆盖原 F。
- 多文件或重复粘贴产生的完全相同课程记录会自动去重，导入前仍统一进入审核表。
- 调研依据与后续 PDF/OCR 路线见 [成绩导入方案调研](outputs/IMPORT_PIPELINE_RESEARCH.md)。

## GPA 计算口径

累计 GPA 使用 `Σ（课程学分 × 课程绩点）÷ Σ计入 GPA 的课程学分`。例如 3 学分课程得到 82 分时，映射为 B+ / 3.5，质量分为 `3 × 3.5 = 10.5`，该课程单独计算时 GPA 为 3.50。F 的学分进入分母但质量分为 0；P/NP 不进入 GPA 分子和分母。
